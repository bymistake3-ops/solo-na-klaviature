# ADR-001: Architecture Decision Records — Analytics Platform

## ADR-001: Backend Framework — FastAPI vs NestJS

**Статус:** Принято  
**Дата:** 2025-04-12

### Контекст
Нужен backend для аналитической платформы с REST API, авторизацией, загрузкой CSV и работой с PostgreSQL.

### Решение: FastAPI (Python)

### Обоснование
- Python лучше подходит для data-pipeline задач (pandas для CSV)
- FastAPI быстро читается и пишется, async-first
- Pydantic v2 для валидации — хорошо интегрируется с SQLAlchemy
- Большая экосистема data-библиотек (pandas, numpy, chardet)
- SQLAlchemy 2.0 async — зрелый, хорошо документированный ORM

### Отвергнутые альтернативы
- **NestJS**: требует TypeScript, хорошо для enterprise, но тяжелее для data-задач
- **Django REST**: более медленный, sync-first

## ADR-002: ORM — SQLAlchemy 2.0 + Alembic

**Статус:** Принято

### Решение

- Хорошая поддержка JSONB (PostgreSQL)

## ADR-003: Schema-driven Data Model

**Статус:** Принято

### Контекст
Нужна расширяемая архитектура — новые CSV не должны требовать изменений кода.

### Решение
Каждый источник данных регистрируется как `DataSource` со schema (JSONB) и column_mapping (JSONB).  
Все строки данных хранятся в `import_rows` с `metrics JSONB` — ключ-значение всех числовых полей.

### Почему это правильно
- Новый CSV → новый `DataSource` запись + column_mapping → без изменений кода
- Новая метрика → новое поле в metrics JSONB → без миграций
- Новый тип данных → новая схема → без рефакторинга
- `metric_definitions` таблица хранит русские названия и единицы — локализация через конфиг

### Схема хранения
```sql
import_rows:
  data_source_id -> data_sources.id
  period_start, period_end
  metrics JSONB  -- {"new_users": 197, "total_amount_gross": 45230.50, ...}
  dimensions JSONB  -- {"segment": "premium", ...}
  raw_data JSONB
```

## ADR-004: Dashboard Widget Configuration

**Статус:** Принято

### Решение
Дашборды и виджеты хранятся в БД (таблицы `dashboards`, `dashboard_widgets`).  
Конфигурация виджета — `JSONB` поле `chart_config`.

### Структура
```json
{
  "widget_type": "line_chart",
  "metric_keys": ["new_users"],
  "chart_config": {
    "colors": ["#3b82f6"],
    "show_legend": true
  },
  "position": {"x": 0, "y": 0, "w": 2, "h": 1}
}
```

### Почему не hardcoded
- Новый виджет = новая запись в БД, не новый код
- Можно конфигурировать через API или UI
- Можно экспортировать/импортировать конфигурации дашбордов

## ADR-005: Auth — JWT + Invite Links

**Статус:** Принято

### Решение
- JWT access token (30 мин) + refresh token (7 дней)
- Регистрация только по invite-link (нет публичной регистрации)
- Токены хранятся в localStorage (frontend)
- Backend stateless (нет session storage)

### Обоснование
- Invite-link проще чем email-invitation для MVP
- Stateless JWT масштабируется лучше
- 30 мин access + 7 дней refresh — стандартный баланс UX/безопасности

### Компромиссы
- localStorage уязвим к XSS — в production рассмотреть httpOnly cookies
- Нет blacklist токенов — logout только client-side

## ADR-006: Frontend — Next.js 14 App Router

**Статус:** Принято

### Решение
Next.js 14 с App Router + TypeScript + Tailwind CSS + Recharts

### Обоснование
- App Router — стандарт для новых Next.js проектов
- Server/Client компоненты разделены явно
- Tailwind CSS — быстрый, низкий overhead
- Recharts — React-native, хорошо работает с TypeScript
- shadcn/ui — компоненты встроенные, не зависимость

### Отвергнутые альтернативы
- **Vite + React SPA**: нет SSR, хуже SEO
- **Remix**: менее зрелая экосистема для аналитики
- **Chart.js**: не React-native, хуже TypeScript support
